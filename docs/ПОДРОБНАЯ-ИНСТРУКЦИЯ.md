# Подробная инструкция: запуск Action & Quality (веб-версия, новый бэкенд)

От «ноль» до работающего сайта с серверным бэкендом — примерно 20 минут. Всё бесплатно на стартовом уровне.

---

## Часть 1. Локальный запуск (2 минуты)

Требуется Node.js 18+ ([nodejs.org](https://nodejs.org), LTS-версия).

```bash
npm install     # один раз
npm run dev     # откроется http://localhost:5173
```

Без каких-либо ключей сайт работает в **demo-режиме**: все данные хранятся в вашем браузере (localStorage), ничего никуда не отправляется. Это уже полноценное приложение — но прогресс живёт только в вашем браузере.

---

## Часть 2. Бэкенд на Supabase (сервер, аккаунты, общие данные)

Supabase — бесплатная облачная база данных Postgres с готовой авторизацией. Наш бэкенд — это 6 SQL-файлов (миграций) в папке `supabase/migrations/`.

### Шаг 2.1. Создать проект

1. Зайдите на [supabase.com](https://supabase.com) → **Start your project** → зарегистрируйтесь (можно через GitHub).
2. **New project** → придумайте имя (например, `action-quality`) → пароль базы **сохраните** → регион выбирайте ближайший (Frankfurt) → **Create new project**. Проект создаётся ~2 минуты.

### Шаг 2.2. Применить миграции — СПОСОБ 1 (рекомендуется, одним файлом)

1. Откройте файл **`supabase/ALL-IN-ONE.sql`** из проекта — это все 6 миграций, собранные в один текст. Файл можно запускать повторно, он ничего не ломает.
2. Supabase → слева **SQL Editor** → **New query**.
3. Скопируйте **весь** текст файла (Ctrl+A в редакторе файла → Ctrl+C) и вставьте в SQL Editor.
4. Нажмите **Run** (Ctrl+Enter).
5. Внизу появится **`Success. No rows returned`** — это УСПЕХ, а не ошибка. Так и должно быть: скрипты создают таблицы, а не возвращают строки.
6. Проверка: слева **Table Editor** — должны появиться таблицы `profiles, habits, habit_logs, moods, quotes, achievements, focus_sessions, game_scores, daily_challenges, plans, broadcasts, friends`.

### Шаг 2.2-бис. СПОСОБ 2 — пофайлово (если нужен контроль)

Те же 6 файлов из `supabase/migrations/` применяются **строго по порядку**, каждый в **новом** запросе SQL Editor: `0001_init.sql` → `0002_games.sql` → `0003_plans.sql` → `0004_broadcasts.sql` → `0005_journal_friends.sql` → `0006_xp_rpc.sql`. Один файл = один Run. Не вставляйте два файла в одно окно.

### Если SQL Editor пишет ошибку

| Текст ошибки | Что делать |
|---|---|
| `relation "..." already exists` / `policy "..." already exists` | Миграции уже применялись (полностью или частично). Либо пропустите этот файл и продолжайте со следующего, либо выполните `supabase/RESET.sql` (удалит все данные проекта!) и после него — `ALL-IN-ONE.sql` заново |
| `relation "profiles" does not exist` (при запуске 0002 и дальше) | Нарушен порядок — сначала должен пройти `0001_init.sql`. Проще всего: RESET.sql → ALL-IN-ONE.sql |
| `syntax error at or near ...` | Скопировался не весь файл или в редактор попал лишний текст (например, заголовок из этой инструкции). Создайте чистый New query и вставьте заново |
| `column "..." does not exist` | Частично применённая старая версия — RESET.sql → ALL-IN-ONE.sql |
| `Success. No rows returned` | **Это не ошибка.** Это успешное выполнение |
| `permission denied` | Вы не в том проекте (слева сверху проверьте название проекта) или не вошли |

Если ошибки нет в списке — пришлите её точный текст, разберём.

### Шаг 2.3. Отключить подтверждение email (важно!)

Вход в приложение идёт по ключу — почты у пользователя нет, поэтому:

1. Слева **Authentication → Providers → Email**.
2. Выключите переключатель **Confirm email** → **Save**.

(Если оставить включённым — вход с нового ключа потребует подтверждения по почте, которой не существует.)

### Шаг 2.4. Скопировать ключи проекта

1. Слева **Project Settings** (шестерёнка) → **API**.
2. Скопируйте два значения:
   - **Project URL** — вида `https://abcdefgh.supabase.co`
   - **anon public key** — длинная строка (публичный ключ, его не страшно отдавать: все права защищены RLS-политиками).

### Шаг 2.5. Подключить ключи к приложению

1. В корне проекта скопируйте `.env.example` → `.env` (именно так, без расширения).
2. Впишите:

```
VITE_SUPABASE_URL=https://abcdefgh.supabase.co
VITE_SUPABASE_ANON_KEY=<anon-ключ из Project Settings → API>
```

3. Перезапустите `npm run dev`. Проверка: зарегистрируйтесь ключом `***админ-ключ*** (выдаётся владельцем)` (Настройки → «Войти по ключу») — в Supabase **Table Editor → profiles** должна появиться строка с ролью `admin`.

> **Бот MAX** (если нужен): после включения Supabase бот продолжает работать — он выдаёт ключи вида `max-<id>@aq.bot`, которые создают аккаунты на сервере. Запуск: `MAX_BOT_TOKEN=<токен> npm run bot`.

## Часть 3. Публикация сайта (чтобы скинуть ссылку / установить на iPhone)

### Вариант А — Netlify Drop (самый простой)

1. Локально соберите сайт: `npm run build` → появится папка `dist/`. В папке `release/` лежит готовый архив **`ActionAndQuality-web.zip`** (после сборки — пересоберите, чтобы попасть в новый бэкенд).
2. Зайдите на [app.netlify.com/drop](https://app.netlify.com/drop) → зарегистрируйтесь (можно через GitHub) → **перетащите zip** в область загрузки.
3. Через ~30 секунд получите постоянный адрес вида `https://random-name.netlify.app`. Его можно поменять: Site settings → Change site name → например, `action-quality.netlify.app`.

### Вариант Б — Vercel

1. Код в GitHub → [vercel.com](https://vercel.com) → **Add New Project** → импорт репозитория → Deploy (настройки определятся сами).
2. Минус: нужен git-репозиторий. Плюс: каждый `git push` обновляет сайт автоматически.

### Вариант В — любой хостинг

`npm run build` → содержимое папки `dist/` (не саму папку) загрузите на любой статический HTTPS-хостинг. Ключи вшиваются в сборку на момент `npm run build` — если поменяли `.env`, пересоберите.

### Важно про домен бэкенда

После публикации зайдите в Supabase → **Authentication → URL Configuration → Site URL** и укажите адрес вашего сайта (например, `https://action-quality.netlify.app`). Правильно для восстановления доступа.

## Часть 4. Установка на устройства

### iPhone (Safari)

1. Откройте ссылку сайта в Safari.
2. Кнопка **Поделиться** (квадрат со стрелкой) → прокрутите → **«На экран “Домой”»** → **Добавить**.
3. На рабочем столе появится розовая иконка. Запуск — на весь экран, как приложение, **работает без интернета** (при первом запуске с сетью скачается кэш).
4. Прогресс хранится в Safari на этом айфоне; вход по ключу привязывает к серверному аккаунту.

### Android (Chrome)

Либо установите **`release/ActionAndQuality-1.0.0-android.apk`** (подписанный; разрешите «Установить неизвестные приложения»), либо как iPhone: Chrome → меню ⋮ → **«Установить приложение»**.

### Windows

- **`release/ActionAndQuality-1.0.0-windows-setup.exe`** — установщик с ярлыками.
- **`release/ActionAndQuality-1.0.0-windows-portable.exe`** — без установки, запуск двойным кликом.

(Эти сборки — офлайн-обёртки; для серверных аккаунтов удобнее сайт.)

### Переслать другу «одним файлом»

`release/ActionAndQuality-offline.html` (~1.4 МБ) — весь сайт в одном файле для **компьютера**: двойной клик в Chrome/Edge → работает без интернета, прогресс в браузере получателя. На iPhone этот формат не годится (ограничение Apple) — только через ссылку из Части 3.

## Часть 5. Пользователи, роли, сообщения команды

- **Гость** (без ключа): роль user, 3 привычки, статистика «Неделя».
- **Ключ `***админ-ключ*** (выдаётся владельцем)`** → роль **admin** (Настройки → «Войти по ключу»). Раздел «Админ-панель»: сводка (регистрации, DAU, привычки), управление пользователями (блокировка, выдача премиума), CRUD цитат, **рассылка на главные экраны** — сообщение появится у всех пользователей в течение минуты (баннер с мегафоном, закрывается крестиком).
- **Ключ `***премиум-ключ*** (выдаётся владельцем)`** → роль **premium**: неограниченные привычки, статистика Месяц/Год, сезонные темы, экспорт PNG.
- **Персональные ключи из бота MAX** (`max-<id>@aq.bot`) → обычные пользователи, привязанные к их аккаунту MAX.

Роли назначаются автоматически по email при первом входе с ключом (SQL-триггер `handle_new_user` в миграции 0001).

## Часть 6. Обновление версии и резервные копии

- **Обновить сайт**: получите новую версию → `npm install` (если менялись зависимости) → `npm run build` → перезалейте `dist/` на хостинг. База данных не трогается; если вышли новые миграции — примените в SQL Editor по порядку.
- **Бэкапы**: Supabase → Database → Backups (на бесплатном тарифе — ежедневные, хранение 7 дней). Дополнительно: «Настройки → Резервная копия» в приложении выгружает demo-данные пользователя в JSON.
- **Новый пользователь**: просто заходит на сайт — создаётся гость; полный аккаунт — ключ от бота или демо-ключи.

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| «Supabase is not configured» | `.env` не создан или не заполнен; после создания перезапустите dev-сервер |
| Вход по новому ключу требует подтверждение почты | Не выключен «Confirm email» (Шаг 2.3) |
| `increment_xp` not found в консоли | Не применена миграция `0006_xp_rpc.sql` (приложение само перейдёт на запасной путь, но примените) |
| Не приходит сообщение от команды | Проверьте, что применена `0004_broadcasts.sql`; сообщение появляется в течение минуты |
| На iPhone после закрытия слетает прогресс | Сайт был открыт без «На экран “Домой”» — установите иконку (Часть 4) |
| APK не ставится | Разрешите «Установка из неизвестных источников» для проводника/браузера |
| Ошибка сети при сохранении | Изменения встанут в офлайн-очередь и отправятся автоматически при возврате интернета (бейдж сверху показывает счётчик) |
